# 协议选课测试版

本测试版依据东北大学选课页面协议的课程列表、先到先得和权重选课行为设计，用于先行验收 App 信息架构与交互，不执行真实选课。

## 页面

- `课程`：使用内置测试教学班验证搜索、分类、余量展示与加入待选池。
- `待选`：调整优先级；权重模式下按每门最低 5 点、总额 100 点做本地预算校验。
- `预览`：展示脱敏后的官方请求形状，运行本地模拟并明确报告未发送请求。

支持的测试批次：

- `typeCode=02`：先到先得请求预览。
- `typeCode=04`：退回旧权重、刷新参数、重投和结果确认的事务预览。

## 安全边界

`EnrollmentSandbox` 没有网络客户端、Cookie/WebView 访问、后台任务或真实提交实现。测试数据的 `clazzId` 与 `batchId` 均使用 `TEST-*` 值；`Authorization` 和 `secretVal` 只显示 `<未读取>` 占位符。

本测试版不会：

- 访问 `jwxk.neu.edu.cn` 或统一身份认证登录态；
- 读取或保存账号、Cookie、token、`secretVal`；
- 调用课程列表、选课、退选或权重接口；
- 创建定时、高频轮询或后台抢课任务；
- 修改应用版本号、发布元数据或 R2 分发内容。

## 正式接入前置条件

用户验收界面后，真实协议层仍需单独设计和审核：当前会话参数采集、速率限制、单实例互斥、轮次校验、结果查询确认、模糊响应处理，以及权重变更失败后的原权重回滚。真实提交应继续与 UI 状态模型隔离，并在发布前使用测试账号和受控批次验证。
